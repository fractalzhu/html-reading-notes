一句话摘要

在 AI agent 时代，HTML 正在取代 Markdown 成为人机协作的最佳输出格式——因为它信息密度更高、更易阅读、可交互、可分享，让人真正"留在回路里"（in the loop）。

读者在阅读过程中建立的独立判断框架——不是复述作者，而是与作者对话后长出来的自己的东西。

判断演化

初始判断

分层而非替代。Markdown 是底层，HTML 是上层。作者的"替代"框架不对——两者各有位置。

中段深化

Markdown 做思考，HTML 做呈现。一个编译隐喻——Markdown 是源码，HTML 是编译产物。思考阶段要省 token、快速迭代；呈现阶段才需要丰富和直观。

新增维度

协作。不只是"给别人看"，而是"跟别人一起调"。面向他人 + 需要共同操作时，HTML 是唯一选项。操作界面把抽象降维成直觉。

终局洞察

格式不是工具选择，是控制力的前提。人的意愿不是自变量，阅读体验才是。你不会因为"应该负责"就逼自己读完 500 行 Markdown，但你可能会因为 HTML 好看就"不小心"读完了。

读者发现的关键概念

动态与静态 · 快照回传

HTML 能做状态捕获：从一个连续的参数空间里钉住一个点（快照），把它固化下来再送回流程。Markdown 是无状态的，做不到。

受众的抽象能力

作者没有显式提出的维度：能读骨架的人用 Markdown 更高效（噪音少）；需要看到"长什么样"才有概念的人需要 HTML 做翻译层。

因果倒置

作者说"我选择用 HTML 来留在回路里"（主动选择）。读者的重新解释：不是人选择留在回路里，而是格式决定了人能不能留在回路里（被动条件）。

终局问题

如果人的控制力取决于格式匹配认知习惯，而 agent 的效率取决于格式轻量可追踪（Markdown），那"对人最好的格式"和"对人机系统最好的格式"可能不是同一个。这个分裂怎么解决？还是说它根本不需要被解决——两层各管各的就行？

英文原文的三层翻译（信·达·雅），适合想细读原文或学习英文技术写作的读者。

骨 引子：Markdown 的局限

直译层（信）
Markdown has become the dominant file format used by agents to communicate with us. It's simple, portable, has some rich text capability and is easy for you to edit. Claude has even gotten surprisingly good at using ASCII to make diagrams inside of markdown files.

Markdown 已成为 agent（智能体）用来与我们沟通的主流文件格式。它简单、可移植、有一定的富文本能力，也便于你编辑。Claude 甚至出乎意料地擅长在 Markdown 文件中用 ASCII 画图表。

But as agents have become more and more powerful, I have felt that markdown has become a restricting format. I find it difficult to read a markdown file of more than a hundred lines.

但随着 agent 越来越强大，我感到 Markdown 正在变成一种限制性格式。超过一百行的 Markdown 文件我就很难读进去了。

I'm also increasingly not editing these files myself, but using them as specs, reference files, brainstorming outputs, etc. When I do make edits, I'm usually prompting Claude to edit them, which removes one of markdown's largest benefits.

我也越来越少亲自编辑这些文件了，而是把它们当作规格说明、参考文件、头脑风暴的产出。即使我要编辑，通常也是让 Claude 来改，这就去掉了 Markdown 最大的优势之一。

意译层（达）

Markdown 曾经是人机协作的通用语言——轻便、好编辑、够用。但当 agent 能做的事越来越复杂、输出越来越长的时候，Markdown 的天花板暴露了：超过百行你根本不想读；你想要颜色、图表、交互，Markdown 给不了；你自己已经不怎么手动编辑文件了，都是让 Claude 改——那 Markdown"人类易编辑"这个核心卖点也站不住了。

点睛层（雅）

关键转折：Markdown 的核心价值主张是 human-editable（人类可编辑），但当人类从"编辑者"变成了"审阅者"（reviewer），编辑权交给了 agent，这个价值主张就被釜底抽薪了。

作者用 "removes one of markdown's largest benefits" ——这是英文技术写作中典型的 understatement（轻描淡写）：语气越平，判断越重。

骨 信息密度

直译层（信）
HTML can convey much richer information compared to markdown. It can of course do simple document structure like headers and formatting, but it can also represent all sorts of other information.

HTML 比 Markdown 能传达丰富得多的信息：表格数据、CSS 设计、SVG 插图、script 代码片段、JS+CSS 交互、SVG/HTML 工作流、绝对定位和 Canvas 空间数据、image 图片。

I would go so far as to say that there is almost no set of information that Claude can read that you cannot fairly efficiently represent with HTML.

几乎没有什么 Claude 能读取的信息是 HTML 不能相当高效地表示的。

意译层（达）

HTML 是一种几乎无上限的表示格式。Markdown 只能做文本结构，但 HTML 能做表格、图表、交互、空间布局、嵌入式代码执行……上限差了一个量级。

骨 双向交互

直译层（信）
HTML can allow you to interact with the document, for example you might want to ask it to add sliders or knobs to adjust a design or allow you to tweak different options in the algorithm to see what happens. You can also ask it to let you copy these changes into a prompt to paste back into Claude Code.

HTML 能让你与文档交互——加滑块或旋钮调整设计，拨弄算法的不同选项看效果。还可以让它提供一个按钮，把调好的参数复制成 prompt 粘回 Claude Code。

点睛层（雅）

"copy these changes into a prompt to paste back into Claude Code" 描述的是一个闭环：Claude 生成 HTML → 人在 HTML 上调参 → 参数变成 prompt → 喂回 Claude。这已经不是"输出格式"的讨论了，这是把 HTML 当作人机协作的中间界面。

骨 Stay in the Loop

直译层（信）
All of the above is to say that I think the real reason I use HTML is that I feel much more in the loop with Claude. I had begun to fear that because I had stopped reading plans in depth I would simply have to leave Claude to make its choices.

归根结底，我用 HTML 的真正原因是它让我感觉自己还在回路里。我曾经开始害怕——因为我已经不再深入阅读计划了，可能只能放手让 Claude 自己做决定。

But I am happy to say instead that I feel more in the loop than ever before when using HTML.

但我很高兴地说，用 HTML 之后，我比以前任何时候都更在回路里。

意译层（达）

全文的落点不是技术比较，而是一种存在性焦虑：当 agent 越来越强，人类正在滑出决策回路。Markdown 因为太难读，加速了这个滑出过程——你不读 plan，就等于放弃了判断权。HTML 把信息重新变得可消化，让人愿意去看，从而重新握住方向盘。

肌 流读段落摘要

Visual Clarity + Ease of Sharing

超过 100 行的 Markdown 自己都不读，更别指望团队读。HTML 用标签页、插图、链接组织结构，上传即可分享。别人真正读你 spec 的概率在 HTML 下高得多。

五个用例

  1. Specs / Planning — 做出一组互相关联的 HTML 文件网络
  2. Code Review — 每个 PR 附一个 HTML 代码解释器
  3. Design & Prototypes — 可调原型 + 滑块调参 + 导出
  4. Reports & Learning — 长文档、交互式讲解器、幻灯片
  5. Custom Editing Interfaces — 为特定数据专门造的一次性工具，关键是以导出结束

FAQ 要点

  • Token 效率：HTML 慢 2-4 倍，但作者认为值得
  • 版本控制：作者承认最大缺点——HTML diffs 嘈杂难审
  • 审美：先生成设计系统 HTML，后续引用保持风格统一
  • 极端立场："I'm probably far on the HTML maximalist side of things"

读者与文本之间的碰撞全记录。每个骨架段都停下来对话——问、答、分析。

碰撞 1：引子段

作者的核心主张

当人类不再是文件的编辑者，Markdown 的核心优势就消失了。

Agent 提问

你同意"当人类不再是文件的编辑者，Markdown 的核心优势就消失了"这个判断吗？

读者回应

底层逻辑上，应该还是 Markdown 是底层，HTML 是基于 Markdown 之上的那一层。太长的 Markdown 偏线性，不是二维的平面展示。但"Markdown 核心优势消失"这个说法让我不太 comfortable。

有多少文件是那种特别长的长文？Markdown 本身非常 simple、straightforward，层级也清楚。HTML 夹杂了其他元素，不那么简单清晰。

Agent 分析

两个独立质疑：

质疑一：Markdown 和 HTML 是"替代"还是"分层"？作者框架是替代，读者感受到的是分层。

质疑二：大多数文件真的那么长吗？如果多数输出是 20-50 行，Markdown 的 simplicity 就不是缺点，而是恰好够用。

读者的不适感有道理：作者把特定场景下的最优解包装成了通用主张。

碰撞 2：划线

Agent 提问

什么情况下该留在 Markdown，什么情况下值得"升格"到 HTML？

读者回应

Markdown 用于简单清晰的场景，骨架信息对齐。HTML 进入 Demo 环节——给需要视觉呈现的受众。对那些不懂的人，或一定要看到"长成什么样"才有概念的人，HTML 更合适。

读者暗含了作者没有显式提出的维度：受众的抽象能力。能读骨架的人用 Markdown 更好（噪音少）；需要看到实际样子才能理解的人需要 HTML 做翻译层。

碰撞 3：信息密度

Agent 提问

这张 HTML 能力清单里，有多少是你日常真正需要的？

读者回应

都是基于展示需求。很多工作可以通过分解完成，沟通思路时文字就足够了。如果 token 多且容错高，HTML 没问题；如果 token 少、要用固定 token 完成最多工作，思路碰撞用 Markdown，最后再用 HTML 呈现。

Markdown 做思考，HTML 做呈现。一个编译隐喻——Markdown 是源码，HTML 是编译产物。Token 成本是作者轻轻带过但读者敏锐捕获的变量。

碰撞 4：双向交互

Agent 提问

这里 HTML 不只是呈现，而是思考工具。这会动摇你之前划的线吗？

读者回应

让我想到"动态与静态"。如果能在交互和调试过程中找到中途的 snapshot（快照），从动态过程中提取静态点再生成切片，回过头来重新运行后续 process，那 HTML 的确具有极大优势。

HTML 能做状态捕获：从连续参数空间里钉住一个点，固化下来再送回流程。Markdown 是无状态的，在原理上做不到。

碰撞 5：协作维度

读者回应

只要工具面向对象是他人，且在思考和设计过程中需要跟他人沟通，那的确很吸引我。

Agent 分析

新维度：不只是"给别人看"（呈现），而是"跟别人一起调"（协作）。文字沟通需要双方有共同的抽象能力，操作界面则把抽象降维成直觉。

碰撞 6：Stay in the Loop

Agent 提问

"留在回路里"的关键，真的是输出格式吗？还是人需要学会什么时候介入、什么时候放手？

读者回应

Agent 读 Markdown 多少行都不累。人因为视觉系统、思维方式、交互偏好，认为 HTML 更容易也更愿意去 review——因为更愿意 review，才有可能发现问题。Markdown 很长时往往是 Agent 写的，人不读，就导致控制力下降。这是一个自我强化的循环。

因果倒置。作者说"我选择用 HTML 来留在回路里"（主动选择）。读者的重新解释：不是人选择留在回路里，而是格式决定了人能不能留在回路里（被动条件）。人的意愿不是自变量，阅读体验才是。
